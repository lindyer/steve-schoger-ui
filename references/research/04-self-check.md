# 三场景自检与独立复核

日期：2026-10-15。对象：本目录的 `steve-schoger-ui`。这是 Skill 的**文字行为自检**，不是商业级 FPDF 的界面验收。

没有取得真实 FPDF 截图、仓库、Theme、可运行程序或用户观察数据。没有运行 Qt/QML、测量真实画布/对比度/查找时间，也没有验证 DPI、键盘、性能和辅助技术效果。不得将本记录转述为“FPDF 测试通过”。

## 实际执行方式

1. 编写三个合成输入，分别模拟工具栏文字需求、属性面板局部 QML、设置弹窗需求与局部 QML。代码只用作静态评审材料，不是可编译工程。
2. 由未参与编写的独立代理读取 Skill 及必要引用，逐项给出方案。没有提供拟定答案，也没有让它读取基线结果；限制为不得修改实现。
3. 主执行代理实际阅读三个响应，检查步骤顺序、建议五要素、归因、数值、未知行为和实施/验证边界。独立代理另做文字审查；这些判断仍有模型自评与合成输入的局限。
4. 另做来源抽查和结构评审，应用有依据的最小修正。完整合成输入与实际生成响应保存在 [05-scenario-record.md](05-scenario-record.md)，可据此复查。

## 基线与窄任务

- 编写前用一个提示充分的合成输入做过一般能力基线，自审**未观察到目标失败**。因此不能宣称新 Skill 修复了已复现错误，或以此证明其优于未使用 Skill 的模型。基线没有正式的来源分层，不构成本 Skill 的来源研究。
- 结构评审另以“只评一个工具栏图标过重、不给 SVG/截图、不改代码”的窄任务干跑。输出只有一个有条件的局部方向，没有强凑第二方案、重排全窗或要求全部平台门禁；图标路径不当作已看过资产。仍然没有真实渲染验证。

## 文件与交付检查的含义

已运行 Skill Creator 的 `quick_validate.py`，结果为 `Skill is valid!`；它只检查 frontmatter、命名和未完成占位，不衡量视觉判断质量。另检查了四份必需文件、九份 Markdown 的 UTF-8 可读性和十八个本地相对链接：文件齐备，无缺失链接或目录外文件依赖。远程来源链接仍需网络才能重新访问，不能将“无目录外文件依赖”理解为离线可重新核验网站。保存设计文档的实际行为回归见上节。
