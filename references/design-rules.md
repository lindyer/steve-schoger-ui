# 可执行视觉规则

本文件是决策工具，不是 Steve Schoger 的原话汇编或像素标准。S/Q 编号见 [sources.md](sources.md)。每条建议在运行时仍须按 SKILL.md 输出具体位置、影响、动作、取舍与验证；以下例子不是对真实 FPDF 的诊断。

## 五个方法视角

以下名称由本 Skill 整理，**不是作者命名的理论，也不声称为其独有发明**。

| 视角 | 有来源支持的方法 | 使用与局限 |
| --- | --- | --- |
| M1 相对层级 | [原始] 字重、颜色和行动主次可承担层级，S01 §1/§7；S02 第51页 | 查“谁在抢注意力”。不能据此无限降低辅助文字对比或强制整款编辑器只有一个主按钮。 |
| M2 用备选检验直觉 | [原始] 探索多个布局，S02 第12页；[归纳] 从 S03 局部改动案例整理成比较过程 | 在相同约束下比较可解释的变量。不能仅因某张示意更漂亮，就推断真实效率更高。 |
| M3 用关系组织信息 | [原始] 分隔可以比较边框、背景、间距等处理，S01 §4、S04 第110/139页 | 查分组是否真实，先找不必要的视觉容器。不能消除输入边界、分隔器和选中反馈。 |
| M4 校正视觉重量 | [原始] 图标尺度、对齐、重量与对比、一致性，S01 §5、S03 第29–40页、S04 第68/104–109页 | 几何相同仍可能看起来失衡。光学校正是局部候选，不能制造新的随机尺寸。 |
| M5 保持颜色关系 | [原始] 彩底文字与背景协调、深色不是直接反相，S01 §2、S02 第75/133–140页 | 关注角色之间的关系；品牌、状态和文档色的解耦是本项目适配，不是原作者给出的完整主题系统。 |

## R01 先按工作任务判断主次

- **适用/定位与影响**：工具栏、属性面板或弹窗里，所有动作同等醒目；用户难以确认当前对象、模式与下一步。
- **方法依据**：[原始] S01 §7 是行动层级策略；[适配] 将其应用到桌面的多任务和持续工具模式。
- **修改动作**：区分常驻命令、当前工具、上下文动作与提交动作。先减弱无必要的实心底色和边框，再检查主对象是否还需加强；主次必须依具体任务决定。
- **取舍/反例**：不可把所有按钮收进菜单来换取整洁；频繁动作、应急取消和任务反馈可能需要持续可见。删除操作在其专门确认弹窗中可能是主动作，但不能为了主次掩盖风险语义。
- **验证**：给定任务，让评审者指出当前工具、可用动作与结果入口；记录误认与查找过程。未做任务观察时，仅能报告视觉假设。

## R02 用字重与对比做层级，克制字号差

- **适用/定位与影响**：组标题、标签、数值、辅助说明全部等重，或标题过大挤压文档与字段。
- **方法依据**：[原始] S01 §1、S02 第51页；[适配] 紧凑桌面优先用已有文字角色。
- **修改动作**：为任务值、字段标签、组标题与辅助文本映射现有字体/字重/文字色角色。先比较同字号下的相对权重；关键标签、单位和错误保持可读。
- **取舍/反例**：减少次要文本对比会降低可读性；不要把“辅助”当成“可以看不清”。输入字段的标签未必可省略，含糊图标和单位必须保留必要文字。
- **验证**：实际字体、中英文、最长标签、浅深主题下检查阅读与截断；灰度预览只辅助判断竞争关系，不能替代对比度和交互检查。

## R03 先确定分组，再调整间距与分隔

- **适用/定位与影响**：工具组难分、属性每行都像独立卡片、嵌套边框和阴影让内容碎片化。
- **方法依据**：[原始] S01 §4、S04 第110/139页；[适配] 密度和画布作为约束。
- **修改动作**：为同任务内容建立对齐与组内节奏，以有限的组间间距、轻背景或必要分隔表明边界；移除没有语义的重复容器。每次比较一种主要分隔方式，避免同时堆叠边框、阴影和大间距。
- **取舍/反例**：输入框轮廓、可拖动面板边界、表格关键分隔可能是操作线索。不要把“少边框”改写为“所有边框都换成阴影”。不规定组间必须为组内某个固定倍数。
- **验证**：相同面板宽度下检查属性归属、可见字段数、内容跳组和扫描顺序；删分隔后重新确认可点击、可编辑和可拖动区域能被识别。

## R04 把密度与画布作为可比较的预算

- **适用/定位与影响**：增加装饰、工具栏行数或面板留白后，文档变窄、可见页内容减少或常用属性需频繁滚动。
- **方法依据**：[适配] 来自 FPDF 项目约束；S04 第58页的间距主题只提供启发，不是桌面扩大留白的命令。
- **修改动作**：优先清除重复框线、无功能标题和过度容器；保留已证明有用的紧凑行列。必要时比较上下文工具或低频命令溢出方案，前提是频率与可发现性有依据。不能靠缩小文字和命中区维持表面密度。
- **取舍/反例**：隐藏命令增加操作层级；折叠面板减少同时可见信息。面板宽度或工具栏高度只有在任务收益足够且获准调整时才改变。
- **验证**：用同一窗口、DPI、PDF 缩放、文档和面板展开状态，记录画布未遮挡净面积、实际可见页内容、可见字段/命令与额外操作数。比例可以辅助比较，不设无来源的通用合格线。

## R05 用多个方案校验判断

- **适用/定位与影响**：仅凭审美偏好重排大量内容，无法解释方案为何更适合任务。
- **方法依据**：[原始] S02 第12页；[归纳] S03 的局部诊断和修改序列；下列比较方法为本 Skill 整理。
- **修改动作**：先写不变量，再指定主要变量。最小方案可只改层级与分隔，进一步方案可调整分组或显隐。相同内容和状态并排比较，记录每案牺牲什么，再提出推荐。
- **取舍/反例**：一个确定的局部错误无需完整探索；缺少任务频率时不能断言把某命令移走最优。A/B 图只能证明外观差别，不自动证明用户效率。
- **验证**：检查比较是否只因不同窗口、缩放或填充内容而占优；让推荐理由对应任务指标。未做观察或测量时，用“预期、待验证”。

## R06 一致图标与光学细节

- **适用/定位与影响**：工具栏图标混合不同笔画、填充风格和视觉尺寸；同尺寸框内个别图标过重，图标放大后模糊或比例失衡。
- **方法依据**：[原始] S01 §5、S03 第29–40页；[适配] Q06 的实际图标解析核验。
- **修改动作**：优先复用现有资产家族、光学尺寸和线条策略；校正图标可见边界、文字基线与按钮内容对齐。图标绘制尺寸、按钮布局尺寸与实际命中区分别检查；不要机械放大小尺寸图标。
- **取舍/反例**：不为遵循风格强行替换语义更明确或平台必需的图标。单个光学校正若必要，应记录到资产或组件，避免各实例随机偏移；命中区不得互相覆盖。
- **验证**：在真实渲染尺寸、浅深背景和 DPI 样本下看像素与重量；确认最终资源是否来自平台主题覆盖。仅图标命令仍有可访问文字与可发现说明，不能只靠悬停。

## R07 表单按阅读和编辑组织

- **适用/定位与影响**：属性标签、数值、单位、步进器未对齐；用户需要来回追踪，错误提示挤坏布局。
- **方法依据**：[原始] S04 第104–109页的对齐/数字主题；[适配] 属性编辑任务与布局约束。
- **修改动作**：统一同类字段的标签列、编辑区域、单位和步进器关系；数值采用适合比较的对齐方式。先在现有紧凑布局内解决；必要时才为长标签改行。数字特性需核实实际字体和 Qt 支持，不能凭空指定 API。
- **取舍/反例**：只为对齐扩宽标签列会吞掉值宽度；所有字段强制同宽可能浪费空间。未知多选混合值时，只列待决定状态，不把破折号或空值当作已定义行为。
- **验证**：最长标签/数值、单位切换、错误、禁用、窄面板、单选和业务已定义的多选样本；检查不截断关键值、不发生横向跳动、组内关系清楚。

## R08 用语义颜色角色承接主题与品牌

- **适用/定位与影响**：组件内硬编码浅色值；换品牌时错误提示、工具选中、批注色和文档内容一起被改色。
- **方法依据**：[原始] S01 §2、S02 第75页只支持颜色关系方法；[适配] 以下 token 架构与业务色分离，技术约束见 Q01/Q05。
- **修改动作**：先清点已有主题 API，再映射基础值 → 语义角色 → 组件状态。示意角色：画布背景、面板表面、输入表面、正文/辅助文字、分隔、品牌、品牌上文字、选择、焦点、禁用、危险/警告/成功；**这些不是现有 FPDF 属性名**。新值附用途和主题映射后进入中央系统。
- **取舍/反例**：不要为一个微小差异建立无复用价值的 token；也不要用同一品牌 token 替代所有语义。用户文档/批注颜色属于内容，不能因应用品牌切换被重写。
- **验证**：浅/深主题分别更换候选品牌，检查按钮上文字、状态、图标、弹出层和自定义绘制。不能假设设置 palette 就覆盖了所有控件。

## R09 深色主题重新安排表面与对比

- **适用/定位与影响**：浅色全局反相后纸张、画布、选区和弹窗混在一起，边框或阴影失效。
- **方法依据**：[原始] S02 第133–140页；[适配] 纸张、选区和桌面表面角色分离。
- **修改动作**：分别决定工作区、面板、浮层、输入区和文字的关系，逐项检查边界与叠层；对品牌底上的文字选择相容且可读的角色。纸张是否启用阅读色由独立功能与用户意图决定，默认不把应用主题当成文档改色授权。
- **取舍/反例**：不设“深色永远不能纯黑/纯白”的作者禁令，也不要求所有深色表面都比背景更亮。阴影在暗背景不够清楚时可比较边界或表面差。
- **验证**：白纸、扫描件、透明内容、彩色图像、文本/批注选区和浮层叠加；比较层级与阅读，不仅比较背景是否变黑。

## R10 状态按持续性与输入反馈分开

- **适用/定位与影响**：hover 看起来像已选中，pressed 结束后标记丢失，焦点被选中背景掩盖，禁用只靠整组透明度。
- **方法依据**：[适配] Qt 状态语义见 Q03/Q04/Q05；这是工程与交互适配，不是从静态作者案例推导的交互规范。
- **修改动作**：默认为基底；hover 表示指针预反馈；pressed/down 为瞬时按压；checked/selected 仅在业务确认时表达持续状态；disabled 表示不可操作；键盘焦点独立叠加。保留 disabled+selected 的必要状态信息，避免以一条互斥颜色链抹掉组合。禁用文本、图标、背景可分别使用角色，不能只有任意整体透明度。
- **取舍/反例**：不是每种控件都应有全部状态；失焦窗口的 inactive 与控件 disabled 不同。错误提示可与焦点共存。焦点表现按项目策略选 visualFocus/activeFocus，不改掉输入控件所需的焦点提示。
- **验证**：鼠标移入/按住/移出释放、键盘导航与激活、持续工具切换、禁用与恢复、选中叠焦点；浅深与品牌样本中可区分状态。真实行为未取得时明确未知。

## R11 文档标签、导航与画布形成稳定参照

- **适用/定位与影响**：活动文档、未保存标记、当前页、导航选中和缩略图边界相互争抢；工具装饰强于文档。
- **方法依据**：[适配] 使用 M1/M3 诊断 FPDF 区域，具体产品行为须由材料证明。
- **修改动作**：区分活动标签与 hover、当前导航项与指针项、文档内容与编辑器背景。对长文件名保留已有识别策略；关闭、未保存、只读、加密等状态只在业务依据存在时设计。页边缘与选区不能与应用分隔线混淆。
- **取舍/反例**：不能单为整齐缩到无法辨认文档，也不能擅自把标签关闭改为仅悬停出现；后者影响可发现性，属于待比较行为。
- **验证**：多文档同名/长名、导航滚动、已定义的未保存状态，白纸与深色内容；检查活动对象在切换前后能被稳定定位。

## R12 弹窗与任务进度只承诺已有行为

- **适用/定位与影响**：设置弹窗按钮同等强调，保存模型不清楚；进度装饰占据工作区，却无法判断状态和后果。
- **方法依据**：[适配] 用 M1/M3 组织界面；保存、阻塞、取消和进度准确性没有作者材料支持。
- **修改动作**：先确认即时应用或显式提交，再排按钮层级、错误、脏状态及关闭路径。只有可计量工作量存在时才显示确定百分比；否则依据真实能力设计不确定进度。取消、后台运行、重试、预计时间需有真实业务支持；无依据就标未知并给条件性方案。
- **取舍/反例**：不为极简隐藏长任务反馈、错误原因或取消入口；不能用假百分比、默认安全关闭或假“剩余时间”制造确定感。阴影只在需要表达浮层关系时考虑。
- **验证**：按已确认模型检查修改、提交、取消、关闭、失败与重开；任务从开始到结束/失败/获支持的取消，关注焦点返回与状态可见。未运行就写计划。

## 常见取舍，不作为人物心理分析

- **低噪音 ↔ 可操作线索**：减装饰后仍能辨认输入、选择、拖拽与焦点。
- **信息密度 ↔ 可读性/可命中性**：保持工作区，但不靠微小字和拥挤热区达成。
- **统一品牌 ↔ 语义与内容真实性**：品牌用于应用角色，错误与文档原色保持各自含义。
- **视觉一致 ↔ 平台差异**：共享系统允许有依据的平台差异；一致外观不等于重写全部原生行为。

遇到冲突，以任务约束和实际验证决定；不得以“Steve 会这样做”为理由越过证据。
