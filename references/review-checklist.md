# 桌面 UI 评审清单

按任务选择适用项。每项记录 **已检查/未检查/不适用/受阻**，附证据和结果；复选框本身不是通过证据。静态评审、代码检查、真实运行、任务观察分开记录。方法对应 [design-rules.md](design-rules.md)，来源范围见 [sources.md](sources.md)。

## 任务与材料

- [ ] 已先说明当前任务、评审区域、用户约束和交付模式；默认只出方案，未把收到 QML 当作修改许可。
- [ ] 区分截图可见、需求明确、代码可证、假设与未知。没有从静态材料猜测多选、快捷键、保存、撤销、任务取消和禁用原因。
- [ ] 标记输入范围、缺少状态、截图缩放与代码读取范围。文件路径/行号经过核对；没有仓库访问时不虚构 Theme API。
- [ ] 每条建议包含位置、影响、动作、取舍、验证，并标原始/归纳/适配；共同作品保留双作者。

## 任务层级与密度

- [ ] 当前文档、当前工具、选择对象和下一步任务可辨；品牌、阴影、边框和字重没有让所有内容同等强调。
- [ ] 优先处理竞争元素，再决定是否放大主元素；辅助文字、单位、错误和必要标签仍能读清。
- [ ] 组内与组间关系清楚，同类内容对齐；没有用逐行大卡片或扩大全部间距替代分组。
- [ ] 保留常用命令与专业密度。隐藏/折叠/溢出方案说明查找与操作成本，并有频率依据或明确假设。
- [ ] 比较窗口、DPI、PDF 缩放、文档、侧栏状态一致；记录画布净面积与实际可见页内容，不能仅用留白或占比判断效率。
- [ ] 没有照搬营销页大标题、大插画、大留白或巨型操作按钮；没有靠缩小字体和命中区保住画布。

## 区域检查

| 区域 | 应观察的内容 | 不能凭外观认定的行为 |
| --- | --- | --- |
| 文档标签 | 活动项、长名/重名、关闭入口、业务已定义的状态标记 | 未保存保护、关闭顺序、标签拖拽和快捷键 |
| 顶部工具栏 | 任务分组、图标重量、当前工具与 hover 区别、窄宽度表现 | 工具互斥、命令频率、溢出规则、按住重复执行 |
| 左侧导航 | 当前页/节点、缩略图边界、展开层级、滚动定位 | 树的键盘模型、拖拽重排、自动跟随策略 |
| 中央画布 | 页边缘、工作区背景、真实内容、选择覆盖和工具装饰竞争 | 文档渲染正确性、编辑后内容、批注持久化 |
| 右侧属性面板 | 字段标签/值/单位关系、分组、错误位置、窄宽度与长值 | 多选混合值、批量应用、即时生效、撤销语义 |
| 弹窗与表单 | 标题/正文/动作主次、字段边界、禁用信息、错误可读 | 保存模型、默认按钮、关闭/取消后果、焦点返回 |
| 任务进度 | 状态文本、确定/不确定呈现、业务支持的控制入口 | 精确百分比、预计时间、可取消、后台运行与重试安全性 |

## 组件与状态

- [ ] 图标家族、笔画、填充、光学尺寸、圆角和基线有一致依据；需要特例时进入资产/组件系统。
- [ ] 绘制尺寸、布局尺寸、实际命中范围分别检查；相邻热区没有重叠，缩放后操作仍可区分。
- [ ] 必要输入边界、拖拽分隔和焦点提示保留；少边框没有导致所有控件失去可操作线索。
- [ ] 默认、hover、selected/checked、pressed/down、disabled、键盘焦点按实际控件语义区分；没有凭空增加可切换行为。
- [ ] 检查 selected+hover、selected+pressed、selected+focus、disabled+selected；适用时检查 error+focus、窗口 inactive。焦点与持续状态没有被瞬时外观覆盖。
- [ ] 禁用标签、图标、说明的可读性分别检查；未用一个未经验证的整体 opacity 值解决所有禁用样式。
- [ ] 图标按钮有可访问文字，必要信息不只在 hover 时出现；业务错误不只靠颜色表达。实际辅助技术支持须运行验证。

## Theme、品牌与实现边界

- [ ] 已查明现有 Theme/tokens、组件库、图标来源和 Controls style；相关 Qt 次版本/API 经过核对。
- [ ] 新值有用途与统一入口；示意 token 明确标“待映射”。没有假称它们是现有接口或作者原始尺寸/色值规范。
- [ ] 浅色和深色分别设计角色关系；未全局反相；品牌底上文字、边框、图标与选区保持可读。
- [ ] 品牌色不覆盖危险/警告/成功语义，也不改变 PDF 内容、批注原色；纸张阅读色与应用主题是独立决定。
- [ ] 根窗口、面板、菜单、tooltip、popup、dialog、overlay 和自定义绘制都检查主题传递；不能假设一个 palette 覆盖全部。
- [ ] 区分主题角色更新与 Controls style 选择；未提出在类型注册后用 QQuickStyle 随意切换 style。
- [ ] 获准实现时，修改集中于必要主题/组件并保留命令、焦点与业务绑定；方案阶段没有偷偷修改实现。

## 验证计划与记录

下面是 **FPDF 建议样本，非 Steve 原始规范**。根据项目支持范围和改动选择，记录实际条件，不因列出样本就宣称执行：

- 浅/深主题，各自的当前品牌与有代表性的替代品牌；检查普通、选中、禁用、焦点和错误组合。
- Windows 可选 100%、125%、150%、200% 缩放；目标最小窗口、常见窗口、混合 DPI 显示器移动。QML 逻辑单位与截图物理像素分别记录。
- 项目实际支持的其他平台；不要求模仿 Windows 的所有原生行为，也不把跨平台渲染当作已验证。
- 长中文/英文文件名、长标签、极值和单位、空态/加载/错误；有业务依据时加入只读、受保护、多选同值/异值。
- 鼠标移入、按住、移出释放；键盘进入/离开面板、焦点可见、激活控件、弹窗关闭与焦点恢复。操作键按实际模型确认。
- 减少动效、系统高对比/辅助技术等按项目要求检查；不能从色值审查或截图直接声称可访问性合规。
- 实现改动时运行项目规定的相关检查；只有性能疑点或新增效果时安排相应性能验证。未运行程序不宣称“更流畅”。

记录模板：

| 检查对象 | 材料/条件与操作 | 预期可观察标准 | 状态 | 实际结果/限制 |
| --- | --- | --- | --- | --- |
| 填具体区域与状态 | 文件/截图/版本、窗口、主题、缩放、内容与步骤 | 如活动工具与键盘焦点同时可辨、无关键文字截断 | 已检查/未检查/不适用/受阻 | 填所见事实；没有运行就不写通过 |

## 提交前反向检查

- [ ] 推荐理由是否可以被反例推翻？是否写明何时不该使用？
- [ ] 两案是否有实质差别，比较条件是否一致？没有为了对照图好看而删掉内容或缩放文档。
- [ ] 有没有“大师规定”“更高级”“更有呼吸感”等无依据结论？将其替换为位置、动作、代价与可观察标准。
- [ ] 有没有把“待运行验证”写成“已通过”，或把合成自检写成真实 FPDF 测试？

三个合成场景的本版本自检见 [research/04-self-check.md](research/04-self-check.md)。它只检查 Skill 输出行为，不能替代真实界面验收。
